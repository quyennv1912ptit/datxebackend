## 2. Authorization & Privilege Escalation Audit

- **Filter & Method Security**: All `/api/admin/**` and `/ekyc/driver-verification/v1/admin/**` routes require `hasRole("ADMIN")` in `FirebaseSecurityConfig.kt:56-57`, plus `@PreAuthorize("hasRole('ADMIN')")` and service-level `requireAdmin(actor)` across controllers/services (verified in `AUTHORIZATION-MATRIX.md`).
- **Admin Exclusivity**: `AuthService#ensureUidAvailableFor` & `loadAuthenticatedUser` strictly refuse authentication if an admin Firebase UID is linked to any customer or driver profile.
- **Self-Approval Guard**: `DriverVerificationWorkflowService#decision` (`L1238`) and `faceComparison` (`L1185`) explicitly block `row.ownerUid == actor.firebaseUid` (`403 FORBIDDEN`).
- **Revoked Token Gap**: Admin HTTP endpoints inherit `FirebaseAuthFilter`'s missing `checkRevoked = true` (`F-016`, already tracked).

## 3. Domain-by-Domain Admin Operations Audit

1. **Ride Operations (`AdminRideService`)**:
   - `assignDriver`: only allowed in `NO_DRIVER_FOUND`, `DRIVER_ASSIGNED`, `DRIVER_ARRIVING` (cannot override `IN_PROGRESS`+). Known P1 bugs already tracked: **`F-001`** (`COMMIT_ADMIN_RIDE_ASSIGNMENT` Lua `ARGV` swap), **`F-002`** (`NO_DRIVER_FOUND` revival double voucher & promo budget corruption).
   - `cancelRide`: delegates to `RideService#cancelRide` (`CANCEL` strictly blocked from `IN_PROGRESS` onward).
2. **Driver Management (`AdminDriverService`, `DriverVerificationWorkflowService`)**:
   - `forceOffline` unconditionally overwrites `BUSY`/`BLOCKED` drivers to `OFFLINE` + `onlineVehicleType=null` without cache eviction (**`F-004`**).
   - `decision(REVOKED/NEEDS_MORE_INFO)` has the same `BUSY`/`BLOCKED` clobber (**`F-020`**), unfiltered `cccd_id_hmac` non-overridable DoS (**`F-017`**), and `faceComparison` DB lock across Modal HTTP (**`F-021`**).
   - No admin driver lock/unlock endpoint exists (**`OBS-11`**).
3. **Customer Management (`AdminCustomerService`)**:
   - `updateStatus`: locks `customers FOR UPDATE`, audits `admin_customer_actions`, cancels `PENDING`/`SEARCHING` rides on `BANNED` (not `INACTIVE` → **`F-031`**), evicts `AuthenticatedUserCache` and revokes Firebase refresh tokens after commit (`F-016` applies to HTTP/STOMP until expiry).
4. **Voucher & Pricing Admin (`PricingRuleService`, `AdminVoucherService`, `PromoBudgetService`)**:
   - `PricingRuleService`: serializes rule activation/deactivation on `findAllByVehicleTypeForUpdate(vehicleType)` and blocks deactivating the last active rule unless `force=true`. Quotes recompute fresh at booking (`1.06`).
   - `PromoBudgetService#setLimit` lacks `FOR UPDATE` (**`F-009`**); other voucher budget bugs tracked in `F-002`, `F-010`, `F-011`, `F-012`, `F-030`.
5. **Payment & Withdrawal Admin (`WithdrawalService`)**:
   - `review(APPROVE/REJECT)` locks `withdrawal_requests FOR UPDATE` and `wallets FOR UPDATE`, verifies `status == PENDING`, prevents duplicate approval/refund. Known gaps: no server-side bank validation or bank snapshot (**`F-007`**), and `deleteDriver` nulls `bankAccountNumber` while `PENDING` withdrawals exist (**`F-024`**).
6. **Support & Disputes (`SupportService`, `TicketService`)**:
   - `claim` and `sendAdminMessage` lock `support_tickets FOR UPDATE` and reject concurrent claims by another admin (`409`). Weak Cloudinary validation on user/admin ticket messages tracked in **`F-028`**.
7. **Audit Log Coverage (Non-Security Observation)**:
   - Audited tables exist for customer status/flag (`admin_customer_actions`), eKYC decisions/overrides (`driver_verification_audit`), ride status (`ride_status_histories`), ratings (`hidden_by`/`hidden_at`/`hidden_reason`), and withdrawals (`reviewed_by`/`reviewed_at`).
   - Missing dedicated audit log tables for `PricingRuleService`, `AdminDriverService#forceOffline`, and `AdminVoucherService` mutations (observability gap, not a security vulnerability).
8. **Read API & PII Exposure**:
   - All admin list endpoints bound `size in 1..100` and `page >= 0`; no unbounded CSV/export endpoints exist.
   - `DriverVerificationWorkflowService#detail(review=true)` intentionally exposes raw `cccdId` to `ADMIN` only (masked `********1234` for driver); capture preview endpoints return `Cache-Control: no-store, private`.

## 5. Confirmed Finding (`1.18`)

### F-032 (`P3` — `CONFIRMED` *(source)*, resolves `OBS-07`) — `AdminRatingService#buildFilters` Filters `LocalDate` Without `Asia/Ho_Chi_Minh` Timezone
- **Location**: [AdminRatingService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/admin/service/AdminRatingService.kt#L205-L213); compare [AdminDashboardService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/admin/service/AdminDashboardService.kt#L21-L24)
- **Root Cause**:
  `AdminRatingService#buildFilters` binds `from.atStartOfDay()` and `to.plusDays(1).atStartOfDay()` as timezone-less `LocalDateTime` values against `ratings.created_at` (`timestamptz`), which JDBC/PostgreSQL evaluates in UTC (container default) rather than `ZoneId.of("Asia/Ho_Chi_Minh")`.
- **Expected vs Actual**:
  Expected: `from=2026-11-23&to=2026-11-23` returns ratings created during `2026-11-23 00:00..23:59 +07:00`. Actual: returns `2026-11-23 07:00..2026-11-24 06:59 +07:00` (7-hour shift).
- **Recommended Fix & Regression Test**:
  Convert using `Timestamp.from(from.atStartOfDay(ZoneId.of("Asia/Ho_Chi_Minh")).toInstant())` (matching `AdminDashboardService`) and add a PG filter test for a rating created at `2026-11-22T18:00:00Z` (`2026-11-23 01:00 +07:00`).
