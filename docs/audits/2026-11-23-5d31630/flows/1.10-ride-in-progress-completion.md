## 2. Guard Verification (`START_TRIP` & `COMPLETE`)

### 2.1 `START_TRIP` (`VEHICLE_HANDOVER → IN_PROGRESS`)
- **Actor & Ownership**: `RideProgressService` requires `Role.DRIVER`; `RideStateMachine#authorize` (`L379-L392`) enforces `actor.userId == ride.driverId` (`403 FORBIDDEN` otherwise).
- **State**: `RideTransitionRules.resolve` requires `VEHICLE_HANDOVER` (`409 INVALID_RIDE_STATE`).
- **eKYC Eligibility**: Locks `drivers FOR UPDATE` (`L106`) and enforces `verification.mayDriveForRide(driver, ride, starting = true, now = now)` (`L108`) — requires `status == BUSY`, `onlineVehicleType == ride.vehicleType`, not flagged/deleted/suspended, `projection.status == APPROVED`, unexpired CCCD/GPLX, exact capability match (`409 DRIVER_NOT_VERIFIED`). *(Affected by `F-004` & `F-020` when `onlineVehicleType` is wiped).*
- **Handover Evidence**: `validateHandover` (`L329-L337`) requires `vehicle_handover_reports(phase = PICKUP)` to exist AND `confirmedByCustomer == true` (`400 HANDOVER_REPORT_REQUIRED`).

### 2.2 `COMPLETE` (`VEHICLE_RETURNED → COMPLETED`)
- **Before Start / Duplicate / After Cancel**: `L103` explicitly enforces `ride.status == RideStatus.VEHICLE_RETURNED`, throwing `InvalidTripStateException` (`409 INVALID_TRIP_STATE`) for any other status (including `IN_PROGRESS`, `CANCELLED`, or duplicate `COMPLETED`). Double-guarded by `compareAndSetStatus(id, "VEHICLE_RETURNED", "COMPLETED", version)` (`L132`).
- **Wrong Actor**: Blocked by `Role.DRIVER` check + `actor.userId == ride.driverId` (`403`).
- **Dropoff Handover Evidence**: `validateHandover` (`L343-L351`) requires `vehicle_handover_reports(phase = DROPOFF)` AND `confirmedByCustomer == true` (`400 HANDOVER_REPORT_REQUIRED`).
- **Locked/Deleted Account**:
  - Deleted driver/customer blocked at HTTP auth layer (`AuthService#loadAuthenticatedUser`); active rides block normal account deletion except under `F-024` race (missing `FOR UPDATE` in `AccountDeletionService`) or `F-016` (open STOMP/revoked token).
- **eKYC Revoked Mid-Trip**: `COMPLETE` intentionally does **not** re-check `mayDriveForRide` (per `V42:80-82`: in-flight trips may finish normally); post-trip `statusAfterRide` moves unapproved driver to `OFFLINE`.
- **Rating Eligibility**: `RideRatingService#rate` (`L138-L145`) enforces `ride.status == COMPLETED`, `completedAt != null`, within 3-day window, 1 rating per direction (`CUSTOMER_TO_DRIVER` / `DRIVER_TO_CUSTOMER`), `tip == 0`.

## 3. Final Fare, Transaction Boundaries & Partial Failure

### 3.1 Final Fare Calculation (`RideStateMachine.kt:158-161`, `MoneyRounding.kt:14-20`)
- **Formula**: Fixed upfront fare — `finalFare = (ride.fareEstimate - ride.discountAmount).coerceAtLeast(0).roundToNearestThousandVnd()` (only computed when `ride.finalFare == null`). No actual-distance, actual-duration, or surcharge recalculation occurs at completion.
- **Rounding & Overflow**: `BigDecimal` `RoundingMode.CEILING` to nearest 1,000 VND via `longValueExact()` (no silent overflow; negative rejected). Rounding surplus accrues to platform; driver net = `80%` of pre-voucher `fareEstimate` (`WalletService#driverNetEarning`).
- **Financial Invariants**: `payments.amount == rides.final_fare`; `ride_wallet_settlements(ride_id)` PK guarantees at-most-once settlement; `promo_budget_ledger` records `SPEND` (`uq_promo_ledger_ride_action`).

### 3.2 Transaction Boundary & Partial Failure Matrix
| Step | Phase | Atomicity / Failure Behavior |
|---|---|---|
| `rides.status = COMPLETED`, `completedAt`, `finalFare`, `ride_status_histories`, `dispatchOffers.closeRide`, `drivers.status = statusAfterRide` | Main `@Transactional` | Single PostgreSQL TX with `rides FOR UPDATE` + `compareAndSetStatus` + `drivers FOR UPDATE`. |
| `PaymentService#onRideCompleted` (`ride_wallet_settlements`, `promoBudget.spend`, `wallets.settle`, `payments`) | `BEFORE_COMMIT` (`Propagation.MANDATORY`) | **Atomic with ride completion**: any settlement/DB failure rolls back the entire TX (`rides` stays `VEHICLE_RETURNED`, `drivers` stays `BUSY`, zero ledger/payment writes). |

## 5. Confirmed Finding (`1.10`)

### F-027 (`P3` — `CONFIRMED`, source) — `DriverVerificationEligibility#statusAfterRide` Restores Expired, Flagged, or `onlineVehicleType=null` Drivers to `ONLINE` & Redis `drivers:geo`
- **Location**: [DriverVerificationEligibility.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationEligibility.kt#L36-L40); [RideStateMachine.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/ride/service/state/RideStateMachine.kt#L172-L179); [RideDispatchRecoveryTask.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/ride/service/RideDispatchRecoveryTask.kt#L96-L104); [DriverReleaseService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/matching/service/DriverReleaseService.kt#L51-L54)
- **Root Cause**:
  ```kotlin
  fun statusAfterRide(driver: Driver): DriverStatus {
      if (displayedStatus(driver) == "APPROVED") return DriverStatus.ONLINE
      driver.onlineVehicleType = null
      return DriverStatus.OFFLINE
  }
  ```
  `displayedStatus(driver)` checks only `driver.verificationStatus != "SUSPENDED"` and `projection.status == APPROVED`. Unlike `mayGoOnline(driver, type)` (`L84-L89`), `statusAfterRide` does **not** check `driver.onlineVehicleType != null`, `driver.isFlagged != true`, `driver.deletedAt == null`, `record.cccdExpiresOn`, or `coversOnline(record.effectiveGroups(today), onlineVehicleType)`.
- **Impact**:
  When a driver completes a ride (or is recovered from `BUSY` by `RideDispatchRecoveryTask`) after their CCCD/GPLX expired mid-ride, after being flagged (`isFlagged = true`), after disabling their capability group, or with `onlineVehicleType == null`, PostgreSQL sets `drivers.status = ONLINE` and `RECONCILE_IDLE` sets Redis `driver:{id}:status = ONLINE` and `GEOADD drivers:geo`. Dispatch still rejects them at `DriverSelectionService#mayDriveForRide`, so no ineligible ride is assigned, but DB/UI show `ONLINE` and Redis `drivers:geo` is polluted with non-dispatchable ghost drivers.
- **Recommended Fix**:
  Delegate `statusAfterRide` to `driver.onlineVehicleType?.let { type -> mayGoOnline(driver, type) } == true`; otherwise clear `driver.onlineVehicleType = null` and return `DriverStatus.OFFLINE`.
