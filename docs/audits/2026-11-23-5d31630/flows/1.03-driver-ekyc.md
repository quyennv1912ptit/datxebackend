- [EkycController.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/ekyc/EkycController.kt) (`POST /api/driver/ekyc/documents/{slot}/extract`, stateless proxy to Modal)

### 1.2 Full Lifecycle Flow
1. **Create (`POST .../applications`)**: `DriverVerificationWorkflowService#create` inserts `driver_verification_applications(status='DRAFT', revision=0)` (1 row per `owner_uid` via `UNIQUE` constraint).
2. **Capture Upload (`PUT .../captures/{slot}?revision=N`)**: Accepts JPEG/PNG/WebP `<= 8 MB`, enforces per-owner DB rate limit (`12/min`), inspects magic bytes & image dimensions (`DriverVerificationStorageService#inspectImage`), deduplicates identical SHA-256 + MIME, encrypts with AES-256-GCM if `app.verification.encryption-key` is configured, retires previous active capture (`retired_at = CURRENT_TIMESTAMP`), increments `revision`, clears `confirmation_current`, and updates `qr_cccd_id_hmac`.
3. **Extraction (`POST .../extract/{slot}`)**: 3-stage split (`Stage A`: `FOR UPDATE` + revision check; `Stage B`: decrypt bytes + call `EkycClient#extract` outside DB TX; `Stage C`: re-lock + verify revision, `capture.id`, `sha256` + store `proposal_json`, increment `revision`, sync `qr_cccd_id_hmac`). Supports `CLASSIFY_ONLY` optimization on `cccd_back` when `cccd_front` QR+OCR matched cleanly.
4. **Live QR Scan (`POST .../qr-scan`)**: Parses Vietnamese CCCD 2021 / Căn cước 2024 / GPLX PET QR payloads (`CccdQrParser`), cross-validates against active OCR fields, persists `qr_live_scan_json` or `gplx_qr_live_scan_json`, syncs `qr_cccd_id_hmac`.
5. **Face Quality (`POST .../face-quality`)**: Validates `faceConsentVersion == "face-comparison-v1"`, reads `FACE_SLOTS` (`cccd_front`, `gplx_front`, `selfie`) outside TX, calls `ekycClient.evaluateFace(images, qualityOnly = true)`.
6. **Confirm Details (`PUT .../confirmation`)**: Validates/canonicalizes CCCD & GPLX fields, enforces `requestedChanges` field allowlist in `NEEDS_MORE_INFO`, enforces `enforceLockedIdentity` (`409 IDENTITY_LOCKED`), computes `cccd_id_hmac`, sets `confirmation_current = true`, increments `revision`.
7. **Submit (`POST .../submit` + `Idempotency-Key`)**: Acquires `FOR UPDATE`, replays `driver_verification_submit_keys` (or throws `409 IDEMPOTENCY_CONFLICT`), verifies all 5 required slots, `confirmation_current`, extraction completion (or prior `EXTRACT_FAILED` audit), `warningAcknowledgementRevision`, computes `applyIdentityHold` for `SEVERE_IDENTITY_CONFLICT_CODES`, writes immutable `driver_verification_submissions` snapshot, transitions to `SUBMITTED`, and syncs `driver_verification_projection` + `drivers` unless `preservePriorApproval = (approvedRevision != null && !applyIdentityHold)`.
8. **Admin Review & Decision (`GET .../admin/review-queue`, `GET .../admin/applications/{id}`, `POST .../face-comparison`, `POST .../decision`)**:
   - Self-review blocked (`row.ownerUid == actor.firebaseUid` → `403 FORBIDDEN`).
   - `decision` locks application `FOR UPDATE`, checks `request.revision == row.revision`, enforces `TRANSITIONS`, evaluates `NON_OVERRIDABLE_BLOCKER_CODES` vs overridable blockers (`allowIdentityOverride=true` requires `reason` and logs `ADMIN_IDENTITY_OVERRIDE`), sets/clears `locked_cccd_id`, `locked_full_name`, `locked_dob`, `verified_gplx_number`, updates `driver_verification_projection` + `drivers` + `driver_capability_preferences` (`reconcilePreferences`), and emits `DRIVER_VERIFICATION_UPDATED` notification after commit.
9. **Re-verification & Cancel (`POST .../reverify`, `POST .../cancel-reverify`)**:
   - `reverify`: `APPROVED`/`REJECTED` → `DRAFT` without touching `driver_verification_projection` or `drivers` (preserves valid prior approval).
   - `cancelReverify`: `DRAFT` (when `approvedRevision != null && !identityHold`) → restores `APPROVED` and un-retires the approved snapshot's captures.

## 2. State Machine Audit

| Current Status | Allowed Transitions | Guard / Condition | Side Effects on Projection & `drivers` |
|---|---|---|---|
| *(none)* → `DRAFT` | `create` | 1 app per `owner_uid` (`UNIQUE`) | None |
| `DRAFT` → `DRAFT` | `replaceCapture`, `extractSlot`, `submitQrLiveScan`, `confirmFields` | `revision == expected`, `FOR UPDATE` | None (writes `cccd_id_hmac` / `qr_cccd_id_hmac` immediately — see **`F-017`**) |
| `DRAFT` → `SUBMITTED` | `submit` | All 5 slots, `confirmation_current`, `Idempotency-Key`, extraction check, warning ack | Preserves prior `APPROVED` projection if `approvedRevision != null && !applyIdentityHold`; else sets projection to `SUBMITTED`/`UNDER_REVIEW` and forces driver `OFFLINE` if `applyIdentityHold` (**`F-020`**) |
| `DRAFT` → `APPROVED` | `cancelReverify` | `approvedRevision != null && approvedSubmissionRevision != null && !identityHold` | Restores approved captures; projection untouched |
| `SUBMITTED` → `UNDER_REVIEW` | `decision` (ADMIN) | Not self, `revision` match | Preserves prior approval if `approvedRevision != null && !identityHold` |
| `UNDER_REVIEW` → `APPROVED` | `decision` (ADMIN) | No `hardBlockers`; overridable blockers require `allowIdentityOverride + reason` | Sets identity lock columns, upserts `APPROVED` projection, reconciles capability preferences, sets `drivers.verification_status='APPROVED'`, `license_verified=true` |
| `UNDER_REVIEW` → `REJECTED` | `decision` (ADMIN) | `reason` required | Preserves prior approval if `approvedRevision != null && !identityHold`; else sets `REJECTED`, forces driver `OFFLINE` (**`F-020`**); **does not clear `cccd_id_hmac`/`qr_cccd_id_hmac`** (**`F-017`**) |
| `UNDER_REVIEW` → `NEEDS_MORE_INFO` | `decision` (ADMIN) | `reason` + at least 1 capture or field | Preserves prior approval if `approvedRevision != null && !identityHold`; else sets `PENDING` and forces driver `OFFLINE` (**`F-020`**) |
| `NEEDS_MORE_INFO` → `SUBMITTED` | `submit` | Requested slots must have new capture IDs; field edits restricted to `requestedChanges.fields` | Same as `DRAFT → SUBMITTED` |
| `APPROVED` → `REVOKED` | `decision` (ADMIN) | `reason` required | Clears `locked_cccd_id`/`verified_gplx_number` (**not** `cccd_id_hmac`/`qr_cccd_id_hmac` — **`F-017`**), sets projection `REVOKED`, forces driver `OFFLINE` even if `BUSY`/`BLOCKED` (**`F-020`**) |
| `APPROVED` → `NEEDS_MORE_INFO` | `decision` (ADMIN) | `reason` + requested targets | `preservePriorApproval = false` → sets projection `NEEDS_MORE_INFO`, forces driver `OFFLINE` even if `BUSY`/`BLOCKED` (**`F-020`**) |
| `APPROVED` / `REJECTED` → `DRAFT` | `reverify` (DRIVER) | `revision` match | Preserves projection & `drivers`; clears `identityHold` only when `approvedRevision == null` |
| `REVOKED` → `NEEDS_MORE_INFO` | `decision` (ADMIN) | `reason` + requested targets | Sets projection `NEEDS_MORE_INFO`, forces driver `OFFLINE` |

### F-017 (`P1` — `CONFIRMED`, source) — Unfiltered `cccd_id_hmac`/`qr_cccd_id_hmac` Enables Cross-Account Permanent Onboarding DoS & Blocks Revoked/Rejected Re-verification
- **Location**: [DriverVerificationWorkflowService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationWorkflowService.kt#L66-L75), [#L837-L850](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationWorkflowService.kt#L837-L850), [#L1340-L1367](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationWorkflowService.kt#L1340-L1367), [#L1942-L2003](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationWorkflowService.kt#L1942-L2003); [V39__identity_lock_and_reverification.sql](file:///f:/datxebackend/src/main/resources/db/migration/V39__identity_lock_and_reverification.sql#L11-L17); [V40__qr_live_scan_and_cccd_hmac.sql](file:///f:/datxebackend/src/main/resources/db/migration/V40__qr_live_scan_and_cccd_hmac.sql#L1-L12)
- **Root Cause**:
  1. `confirmFields` (`L837-L850`) writes `cccd_id_hmac` and `submitQrLiveScan`/`extractSlot`/`replaceCapture` write `qr_cccd_id_hmac` while the application is still in **`DRAFT`** (unsubmitted, unverified).
  2. `hasDuplicateCccdAcrossAccounts` (`L1946-L1953`) filters:
     ```sql
     WHERE owner_uid <> ?
       AND (locked_cccd_id = ?
            OR cccd_id_hmac = ?
            OR qr_cccd_id_hmac = ?
            OR status IN ('APPROVED', 'SUBMITTED', 'UNDER_REVIEW', 'NEEDS_MORE_INFO'))
     ```
     There is **no `status` predicate** on `cccd_id_hmac` or `qr_cccd_id_hmac`, and `decision(REJECTED)` / `decision(REVOKED)` (`L1340-L1367`) **never clears** `cccd_id_hmac` or `qr_cccd_id_hmac`.
  3. `DUPLICATE_CCCD_ACROSS_ACCOUNTS` is in `NON_OVERRIDABLE_BLOCKER_CODES` (`L73`), so `decision(APPROVED)` unconditionally throws `409 VERIFICATION_ACTIVATION_BLOCKED` even when an admin passes `allowIdentityOverride = true`.
  4. Compounding weaknesses in the same duplicate-check layer:
     - `V39` / `V40` define only non-unique indexes on `locked_cccd_id`, `verified_gplx_number`, `cccd_id_hmac`, `qr_cccd_id_hmac` (no DB-level `UNIQUE` partial index enforcing one active identity per account under concurrency).
     - Both `hasDuplicateCccdAcrossAccounts` (`L1945`) and `hasDuplicateGplxAcrossAccounts` (`L1981`) wrap the query and Kotlin JSON deserialization of every row's `confirmed_fields` in `runCatching { ... }.getOrDefault(false)` — **failing open** (`false`) if any row contains malformed JSON or a transient DB error occurs, while performing an O(N) scan of all active applications on every `detail`/`confirm`/`submit`/`decision`.
- **Impact**:
  - Any authenticated `DRIVER` knowing a victim's 12-digit CCCD number can create a `DRAFT` application and call `PUT .../confirmation` or `POST .../qr-scan` (never submitting) to permanently squat the victim's `cccd_id_hmac`. The victim can never be approved (`409 VERIFICATION_ACTIVATION_BLOCKED`), and **no admin can override or clear the block** (even rejecting/revoking the squatter's application leaves `cccd_id_hmac` intact).
  - Any driver whose previous account was `REJECTED` or `REVOKED` is also permanently unable to verify on a new account.
- **Recommended Fix**:
  - Scope duplicate CCCD/GPLX blocking to active/verified statuses (`status IN ('APPROVED', 'SUBMITTED', 'UNDER_REVIEW', 'NEEDS_MORE_INFO')` or `locked_cccd_id IS NOT NULL`), clear `cccd_id_hmac` and `qr_cccd_id_hmac` on `REVOKED`/`REJECTED`/account deletion, add PostgreSQL `UNIQUE` partial indexes on `(locked_cccd_id) WHERE locked_cccd_id IS NOT NULL` and `(UPPER(TRIM(verified_gplx_number))) WHERE verified_gplx_number IS NOT NULL`, and fail closed (do not swallow DB/parse exceptions via `getOrDefault(false)`).

### F-018 (`P2` — `CONFIRMED`, source) — Account Deletion Leaves eKYC PII & Capture Files Intact, Permanently Blocking Re-Registration & Accumulating Orphan Files
- **Location**: [AccountDeletionService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/auth/service/AccountDeletionService.kt#L98-L138); [AccountCleanupOutboxWorker.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/auth/service/AccountCleanupOutboxWorker.kt#L21-L60); [DriverVerificationStorageService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationStorageService.kt#L98-L129)
- **Root Cause**:
  1. `AccountDeletionService#deleteDriver` tombstones `drivers.firebase_uid` and anonymizes `drivers`, deletes `device_tokens`/`notifications`/`driver_vehicle_skills`, and enqueues Firebase user + Cloudinary avatar deletion. It **never touches** `driver_verification_applications`, `driver_verification_submissions`, `driver_verification_captures`, `driver_verification_projection`, `driver_verification_audit`, `driver_capability_preferences`, or local capture files on disk.
  2. `DriverVerificationStorageService#deleteQuietly` is only called on DB insert failure in `replaceCapture` (`L465`). Unsubmitted retired captures (`retired_at IS NOT NULL AND first_submitted_revision IS NULL`) are never garbage-collected from disk.
- **Impact**:
  - **PII Retention Violation**: Full raw CCCD number (`locked_cccd_id`, `confirmed_fields`, `snapshot_json`), full name, DOB, GPLX number, and all CCCD/GPLX/selfie image files remain permanently in PostgreSQL and on disk after `DELETE /api/auth/account`.
  - **Permanent Self-Lockout on Re-Registration**: Because the deleted driver's `driver_verification_applications` row stays `APPROVED` with `locked_cccd_id`, `verified_gplx_number`, and `cccd_id_hmac` under the old `firebase_uid`, re-registering with the same real CCCD/GPLX permanently fails with non-overridable `DUPLICATE_CCCD_ACROSS_ACCOUNTS` / `DUPLICATE_GPLX_ACROSS_ACCOUNTS`.
  - **Unbounded Disk Growth**: Repeated capture replacements before submission leave orphan sensitive ID files permanently on disk.
- **Recommended Fix**:
  - On `deleteDriver`, revoke/anonymize or purge verification records (subject to legal retention policy: if regulatory retention is required, move to an isolated archive table outside active duplicate checks and clear `locked_cccd_id`/`verified_gplx_number`/`cccd_id_hmac`/`qr_cccd_id_hmac` + `driver_verification_projection`), enqueue capture file deletion in `AccountCleanupOutboxWorker`, and add a scheduled cleanup job for unsubmitted retired captures (`retired_at < now() - interval '24 hours' AND first_submitted_revision IS NULL`).

### F-019 (`P2` — `CONFIRMED`, source, resolves `OBS-05`) — Ephemeral `lookupHmacSecret` Fallback, AES/HMAC Key Reuse & Zero Key-Rotation Support
- **Location**: [DriverVerificationWorkflowService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationWorkflowService.kt#L99-L106); [DriverVerificationStorageService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationStorageService.kt#L37-L61), [#L106-L125](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationStorageService.kt#L106-L125)
- **Root Cause**:
  1. `DriverVerificationWorkflowService` binds `lookupHmacKey` via `@Value("${app.verification.lookup-hmac-key:${app.verification.encryption-key:}}")`. When both are blank (non-protected / staging / dev), `lookupHmacSecret` silently falls back to `SecureRandom().nextBytes(ByteArray(32))` (`L106`) — a new ephemeral key on every JVM startup and different per replica.
  2. In `production` (`require-protected-storage=true`), `DriverVerificationStorageService` enforces non-blank `encryption-key`, causing `lookupHmacKey` to silently reuse the **same master secret** (`SHA-256(encryptionKey)`) for both AES-256-GCM capture encryption and HMAC-SHA256 identity lookup if `DATXE_VERIFICATION_LOOKUP_HMAC_KEY` is not separately provisioned.
  3. Neither `DriverVerificationStorageService` (fixed magic header `DXE1` with no `keyId`) nor `DriverVerificationWorkflowService` supports key versioning or multi-key rotation.
- **Impact**:
  - Restarts or multi-instance deployments without an explicit `DATXE_VERIFICATION_LOOKUP_HMAC_KEY` invalidate HMAC index lookups (`cccd_id_hmac`, `qr_cccd_id_hmac`).
  - Rotating `DATXE_VERIFICATION_ENCRYPTION_KEY` in production immediately breaks `storage.read()` (`AEADBadTagException` → `500`/`503`) for **all** existing driver CCCD/GPLX/selfie captures, breaking admin review and historical snapshots.
  - Rotating `DATXE_VERIFICATION_LOOKUP_HMAC_KEY` breaks all persisted HMAC digests with no re-hashing migration path.
- **Recommended Fix**:
  - Require explicit `DATXE_VERIFICATION_LOOKUP_HMAC_KEY` distinct from `DATXE_VERIFICATION_ENCRYPTION_KEY` when `require-protected-storage=true` (fail fast at startup instead of ephemeral fallback or key reuse).
  - Add a key-version header (`DXE2 + keyId`) and keyring support (`currentKey` + `previousKeys`) in `DriverVerificationStorageService` and multi-key HMAC lookup + re-encryption/re-hash batch tooling.

### F-020 (`P1` — `CONFIRMED`, source, variant of `F-004`) — `syncProjectionAndDriver` Overwrites `BUSY` / `BLOCKED` Drivers to `OFFLINE` + `onlineVehicleType=null`
- **Location**: [DriverVerificationWorkflowService.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationWorkflowService.kt#L1467-L1509); compare [V42__remove_legacy_driver_verification.sql](file:///f:/datxebackend/src/main/resources/db/migration/V42__remove_legacy_driver_verification.sql#L89-L107) and [DriverVerificationEligibility.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/driver/verification/DriverVerificationEligibility.kt#L63-L65)
- **Root Cause**:
  In `syncProjectionAndDriver`, all non-approval branches (`REJECTED`, `REVOKED`, `NEEDS_MORE_INFO`, and `SUBMITTED`/`UNDER_REVIEW` when `takeDriverOffline = applyIdentityHold`) unconditionally execute:
  ```kotlin
  lockedDriver.status = DriverStatus.OFFLINE
  lockedDriver.onlineVehicleType = null
  ```
  and schedule `locationService?.removeDriver(lockedDriver.id)` after commit, **without checking** whether `lockedDriver.status == DriverStatus.BUSY` (on an active ride) or `lockedDriver.status == DriverStatus.BLOCKED`.
- **Concrete Interleaving / Impact**:
  1. **Active ride bricked**: Driver is `APPROVED` and `BUSY` (`DRIVER_ASSIGNED` → `VEHICLE_HANDOVER`).   2. **Ban status clobbered**: If the driver was previously `DriverStatus.BLOCKED` by an admin, revoking or requesting more info overwrites `drivers.status` from `BLOCKED` to `OFFLINE`.
- **Recommended Fix**:
  - Preserve `DriverStatus.BLOCKED` and `DriverStatus.BUSY` (or active rides per `V42:89-107`): only transition `ONLINE → OFFLINE` and clear `onlineVehicleType` when `lockedDriver.status == DriverStatus.ONLINE` and no active ride exists; for `BUSY` drivers, let `RideStateMachine#completeTrip` (`statusAfterRide`) take them `OFFLINE` after the in-flight ride completes (and fix `statusAfterRide` to check `effectiveGroups` + `BLOCKED`/`isFlagged`, not only `displayedStatus`).

## 4. Additional Security, Concurrency, Eligibility & Variant Checks

### 4.1 Concurrency Matrix
| Race Pair | Serialization Mechanism | Verdict |
|---|---|---|
| `submit` vs `decision(APPROVED)` | Both lock `driver_verification_applications(id) FOR UPDATE`; state (`DRAFT`/`NEEDS_MORE_INFO` vs `UNDER_REVIEW`) & `revision` disjoint | **SAFE** |
| `decision(APPROVED)` vs `decision(REJECTED)` | Both lock `driver_verification_applications(id) FOR UPDATE` + optimistic `revision` check | **SAFE** |
| `replaceCapture` vs `decision` / `faceComparison` | `replaceCapture` requires `EDITABLE_STATES`; `adminDetail` uses `revisionCutoff` + immutable `driver_verification_submissions` snapshot | **SAFE** (note `faceComparison` lock-hold bug in **`F-021`**) |
| `reverify` / `decision(REVOKED)` vs Active Ride (`BUSY`) | `reverify` itself is safe, but `applyIdentityHold` on `submit` and `decision(REVOKED/NEEDS_MORE_INFO)` call `syncProjectionAndDriver` without checking `BUSY` | **VULNERABLE (`F-020`)** |

### 4.3 Modal eKYC Integration & Capture Storage Security
- **Modal Security (`EkycConfig`, `EkycClient`, `EkycController`)**: Origin strictly pinned to `https://*.modal.run` with `Redirect.NEVER`, no port/path/query/fragment/userInfo; bounded timeouts (`5s` connect, `65s` read, `75s` total deadline); `Semaphore(2)` concurrency cap; retries bounded to `502`/`503`/`ENGINE_BUSY`/non-timeout network errors (never retries `504`/timeout/`429`/`4xx`/`JacksonException`); response size capped at `256 KB` and validated for `slot` + `candidates`/`data` shape; `Cache-Control: no-store`; zero PII logged.
- **Capture Storage (`DriverVerificationStorageService`)**: Path traversal blocked (`^[A-Za-z0-9_-]{8,128}$` + `resolved.startsWith(root)`); magic-byte + ImageIO/WebP dimension validation (`<= 8 MB`, `<= 40 MP`); AES-256-GCM with 12-byte `SecureRandom` IV; SHA-256 + byte-size integrity check on read; production profile enforces `require-protected-storage=true` (absolute path outside app dir + non-blank encryption key). Gaps: key rotation (`F-019`) and orphan/deletion cleanup (`F-018`).
- **Profile Display Name (`DriverProfileService#updateIdentity`)**: Allows `APPROVED` drivers to edit `drivers.fullName` without checking `locked_full_name`. Does not bypass eKYC identity lock, but causes customer-visible driver name to diverge from verified CCCD name (hardening note).

### 4.4 Variants of `F-004`, `F-014`, `F-016`
