## 4. New Confirmed Finding (`2.02`)

### F-051 (`P3` — `CONFIRMED` *(source)*) — `TIMESTAMP WITHOUT TIME ZONE` Columns With `DEFAULT CURRENT_TIMESTAMP` Risk 7-Hour Timestamp Drift Under Non-UTC PostgreSQL Sessions
- **ID / Severity / Confidence**: `F-051` | **P3** | **High** (`CONFIRMED` *(source)*)
- **Location**: [V18__wallet_module.sql](file:///f:/datxebackend/src/main/resources/db/migration/V18__wallet_module.sql#L25-L26,L49), [V1__init.sql](file:///f:/datxebackend/src/main/resources/db/migration/V1__init.sql#L81,L276,L355-L356)
- **Affected Tables/Columns**: `withdrawal_requests(reviewed_at, created_at)`, `ride_wallet_settlements(created_at)`, `wallet_transactions(created_at, updated_at)`, `drivers(last_location_update)`, `customers(last_login_at)`.
- **Preconditions**: PostgreSQL server/session `TimeZone` is not `UTC` (e.g., `Asia/Ho_Chi_Minh` on local/managed Postgres) while JVM/Hibernate uses `spring.jpa.properties.hibernate.jdbc.time_zone=UTC`.
- **Expected Behavior**: All timestamp columns use `timestamptz` (`TIMESTAMP WITH TIME ZONE`) so `DEFAULT CURRENT_TIMESTAMP` and JDBC/JPA reads are timezone-invariant.
- **Actual Behavior**: These 7 columns use `timestamp` (`TIMESTAMP WITHOUT TIME ZONE`). When rows are inserted via SQL `DEFAULT CURRENT_TIMESTAMP` (e.g., `ride_wallet_settlements`, `withdrawal_requests`, `wallet_transactions`), PostgreSQL strips the session offset, storing local wall-clock time; Hibernate then reads it back interpreting it as UTC, shifting financial ledger timestamps by 7 hours.
- **Root Cause**: Inconsistent column type (`timestamp` instead of `timestamptz`) in `V1` and `V18`.
- **Business Impact**: 7-hour ledger/withdrawal timestamp drift in non-UTC PostgreSQL environments, complicating financial reconciliation and audit trails.
- **Recommended Fix**: Add a Flyway migration converting these columns to `TIMESTAMPTZ USING <col> AT TIME ZONE 'UTC'` (and ensure DB session timezone is pinned to `UTC` in `connection-init-sql`).
- **Suggested Regression Test**: PostgreSQL test setting `SET LOCAL TIME ZONE 'Asia/Ho_Chi_Minh'`, inserting a `withdrawal_requests` row via `DEFAULT CURRENT_TIMESTAMP`, and asserting the read `Instant` is within 5s of `Instant.now()`.
