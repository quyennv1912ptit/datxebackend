## 3. `F-001` (P1) — Runtime Verification on Disposable Redis 7 (`CONFIRMED (runtime)`)

Executed the exact `COMMIT_ADMIN_RIDE_ASSIGNMENT` Lua script from `AdminRideService.kt:332-353` against a disposable `redis:7-alpine` container (`ptitgo_audit_redis_tmp`, port `127.0.0.1:6399`, stopped & removed immediately after):
- **Setup**: Ride `99` assigned to Old Driver `10` (`driver:10:current_ride = 99`, `driver:10:status = BUSY`); Admin reserves New Driver `20` (`driver:20:lock = admin:99:20 EX 30`, `available_drivers` contains `20` and `99`).
- **Observed Output**:
  ```text
  LUA_RETURN=1
  OLD_DRIVER_10_CURRENT_RIDE=99
  OLD_DRIVER_10_CURRENT_RIDE_TTL=-1
  OLD_DRIVER_10_STATUS=OFFLINE
  NEW_DRIVER_20_CURRENT_RIDE=99
  NEW_DRIVER_20_STILL_IN_GEO=True
  RIDE_99_REMOVED_FROM_GEO=True
  DISPOSABLE_REDIS_STOPPED=true
  ```
- **Confirmed Impact**: Old Driver `10` keeps `driver:10:current_ride = 99` with `TTL = -1` and `driver:10:status = OFFLINE`; `RideDispatchRecoveryTask.kt:114` skips `OFFLINE` drivers, so Driver `10` receives `409 DRIVER_NOT_AVAILABLE` forever on `PUT /api/driver/availability (online=true)`. Meanwhile, `ZREM available_drivers 99` fails to remove New Driver `20` and would evict unrelated Driver `99` if present.

## 4. Failure, Recovery & Multi-Instance Analysis

- **DB Commit Succeeds, Redis Update Fails**:
  - `DriverPresenceService` / `DriverReleaseService` / `AdminRideService` log warning/error in `afterCommit` (no DB rollback). `RideDispatchRecoveryTask` (10s) restores active `BUSY` rides from PostgreSQL to Redis and reconciles orphaned `BUSY`/`ON_TRIP`/`OFFERED` Redis keys — **except** `OFFLINE` drivers with stale `current_ride` (`F-001`) and `DriverCapabilityService#update` (`F-044`).
- **Redis Restart (Empty Memory)**:
  - `LocationService#saveDriverLocation:85` checks PostgreSQL `activeRide` before calling `ADD_AVAILABLE`, preventing an assigned driver from re-entering `available_drivers` after a Redis restart. `RideDispatchRecoveryTask` repopulates `driver:{id}:current_ride` and `driver:{id}:status = BUSY` for all active rides within 10s.
- **Multi-Instance Coordination**:
  - Redis Lua locks (`ride:{id}:tick`, `driver:{id}:lock`, `INCREMENT_WITH_EXPIRY`) and PG `FOR UPDATE` locks are multi-instance safe.
  - Local JVM state limits: `AuthenticatedUserCache` (3s TTL, local eviction only) and `SimpleBrokerMessageHandler` (single-node STOMP sessions, already noted in `1.17`/`1.21`).
