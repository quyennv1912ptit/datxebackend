## 2. `F-014` (P1) — Runtime Verification (`CONFIRMED (runtime)`)

Verified in an isolated in-memory harness (`scratch/StompF014Check.java`, outside repository, zero edits to `src/**`, zero external network) wiring the production `StompAuthInterceptor` directly to Spring's `DefaultSimpUserRegistry`, `DefaultUserDestinationResolver`, `UserDestinationMessageHandler`, and `SimpleBrokerMessageHandler` (`/queue`, `/topic`) with two synthetic principals (`CUSTOMER:1` and `CUSTOMER:2`):

```text
STOMP CONNECT ok principal=CUSTOMER:1 session=sess-a
STOMP CONNECT ok principal=CUSTOMER:2 session=sess-b
BROKER_CH cmd=SUBSCRIBE type=SUBSCRIBE dest=/queue/trip-usersess-b sess=sess-b
CHECK_TOPIC_SUBSCRIBE_BLOCKED=true msg=Không được phép subscribe /topic/rides/99/location
BROKER_CH cmd=SEND type=MESSAGE dest=/queue/trip-usersess-b sess=sess-a
VICTIM_RECEIVED session=sess-b dest=/queue/trip-usersess-b payload={"type":"PAYMENT_UPDATED","payload":{"rideId":99,"status":"PAID"}}
F014_RUNTIME_DELIVERED_TO_VICTIM=true
```

- **Confirmed at Runtime**:
  1. `SUBSCRIBE /topic/rides/99/location` is **strictly blocked** by `StompAuthInterceptor` (`MessagingException`).
  2. `SEND /user/CUSTOMER:2/queue/trip` from `CUSTOMER:1` passes `StompAuthInterceptor.kt:38`, is rewritten by `UserDestinationMessageHandler` to `/queue/trip-usersess-b`, and is **delivered by `SimpleBrokerMessageHandler` directly into victim `CUSTOMER:2`'s outbound channel** — allowing spoofing of `PAYMENT_UPDATED`, `RIDE_OFFER`, `RIDE_ASSIGNED`, `CHAT_MESSAGE`, and `/user/{victim}/queue/rides/{rideId}/location`.
- **Safe Immediate Containment**: Restrict `StompCommand.SEND` in `StompAuthInterceptor.kt:38` to `destination?.startsWith("/app/") == true` (throwing `MessagingException` otherwise).

## 4. New Confirmed Finding (`2.01`)

### F-050 (`P3` — `CONFIRMED` *(source)*) — Hardcoded `localhost` CORS Origins in Production & Wildcard `allowedOriginPatterns("*")` With `allowCredentials=true` on `/ws-location`
- **ID / Severity / Confidence**: `F-050` | **P3** | **High** (`CONFIRMED` *(source)*)
- **Location**: [FirebaseSecurityConfig.kt](file:///f:/datxebackend/src/main/kotlin/com/nhom15/datxebackend/auth/security/FirebaseSecurityConfig.kt#L86-L118)
- **Entrypoint**: Global CORS filter (`/**` and `/ws-location/**`)
- **Preconditions**: Backend deployed in `production`/`prod` profile.
- **Expected Behavior**: Production CORS allowlist is driven solely by `app.cors.allowed-origins` (excluding `http://localhost:3000` and `http://localhost:5173`), and `/ws-location` sets `allowCredentials = false` when using `allowedOriginPatterns = listOf("*")` (since STOMP authenticates via `CONNECT` Bearer header, not cookies).
- **Actual Behavior**: `FirebaseSecurityConfig#corsConfigurationSource` hardcodes `"http://localhost:3000"` and `"http://localhost:5173"` unconditionally into `allowedOriginPatterns` for `/**`, and sets `allowedOriginPatterns = listOf("*")` with `allowCredentials = true` on `/ws-location` and `/ws-location/**`.
- **Root Cause**: Dev origins hardcoded in `FirebaseSecurityConfig` instead of profile-specific `application-dev.properties`, and unnecessary `allowCredentials = true` on wildcard WebSocket CORS.
- **Exploitability / Blast Radius**: Low (API uses Bearer headers rather than cookies, limiting classic CSRF), but broadens cross-origin trust surface from local dev ports and reflects arbitrary `Origin` with `Access-Control-Allow-Credentials: true` on `/ws-location`.
- **Recommended Fix**: Move `localhost:3000`/`5173` out of Kotlin code into `app.cors.allowed-origins` default (overridden in prod env), and set `allowCredentials = false` on `websocketConfig`.
- **Suggested Regression Test**: MockMvc test with `production` profile verifying `Origin: http://localhost:3000` is rejected on `/api/**` and `/ws-location` does not emit `Access-Control-Allow-Credentials: true` for arbitrary origins.
